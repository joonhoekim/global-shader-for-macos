## 지운 셰이더 셋

한때 `cyberpunk/rain.frag`(빗방울) · `print/riso.frag`(리소 망점) ·
`print/dither.frag`(게임보이 4색)이 더 있었다. 리눅스 쪽 하이프랜드 세션에서
실제로 걸어 보고 지웠다 — 셋 다 본문을 못 읽게 만드는데 그 대가로 얻는 룩이
값어치가 없었다. 개선 여지가 아예 없지는 않았다. `rain.frag` 은 형제인
`water/still.frag` 의 `busy()` 를 가져오면 글자 밭에서 굴절을 접을 수 있었고,
`dither.frag` 은 `PIXEL` 을 내리면 나아졌다. 그래도 셋 다 "읽으면서 쓸 룩"이
되지는 못한다. `dither.frag` 은 원리적으로 그렇다 — 글자를 지키려면 픽셀화를
안 해야 하고, 그러면 그 셰이더가 아니다.

새 셰이더를 받는 기준이 이것이고, [`CONTRIBUTING.md`](../../CONTRIBUTING.md) 에
그렇게 적혀 있다(영어). 인쇄 갈래가 그 기준이 가장 또렷하게 드러난 자리다.
`riso.frag` 과 `dither.frag` 은 가독성을 내주고 룩을 얻었고, 셋 중 살아남은
한 장은 유일하게 **읽으려고** 만든 것이다 — 우연이 아니다.

폴더 모양도 이때 정해졌다. 폴더가 곧 갈래 이름이고, 메뉴 막대의 `체인 → 더하기`
도 이 모양 그대로 접힌다. 파일이 서넛일 때는 한 단에 늘어놓는 게 맞았지만 열둘이
되면서 갈렸다 — 이름을 하나씩 읽어야 무엇인지 알 수 있는 목록은 목록이 아니다.

## `crt.frag` 과 `crt-motion.frag` 을 한 장으로

브라운관 파일이 둘이었다. 흐르는 것(그레인·험 바·클릭 리플)이 든 판과 안 든
판이고, 나눈 이유는 재그리기였다 — `time` 을 읽는 셰이더는 계속 그려야 하니,
정지 화면에서 공짜로 두려고 안 흐르는 판을 따로 뒀다([손잡이](../knobs.ko.md)).

**그 판단이 틀렸다기보다, 지키기로 한 것을 못 지켰다.** 합치기 전에 둘을
대조했다:

```
curve · gun · focusAt · bloom · stripes · bezel   주석 뺀 코드 차이 0 줄
crt.frag 에만 있는 #define                        없음 (motion 쪽이 초집합)
FOCUS                                            0.18  vs  0.32   ← 어긋남
FOCUS_NEAR                                       0.25  vs  0.28   ← 어긋남
```

`crt-motion.frag` 머리말에는 "여기를 고치면 `./crt.frag` 도 같이 고쳐야 한다"고
적혀 있었다. 적어 두는 것으로는 안 된다는 것이 저 두 줄이다. 복제가 부르는 실패는
"언젠가 어긋날 수 있다"가 아니라 이미 일어난 일이었다.

어긋난 둘은 `crt.frag` 쪽(0.18 / 0.25)으로 맞췄다. 그쪽 주석이 왜 0.5 에서 거기까지
내려왔는지를 적고 있고, motion 쪽 0.32 는 그 판단이 반영되기 전의 복사본이었기
때문이다. 손잡이라 화면 보고 되돌리면 된다.

옛 `crt.frag`(안 흐르는 판)을 그대로 얻으려면:

```sh
global-shader --set GRAIN 0
global-shader --set HUM 0 && global-shader --set HUM_LIFT 0 && global-shader --set HUM_GLOW 0
global-shader --set RIPPLE_GAIN 0 && global-shader --set RIPPLE_LIFT 0 && global-shader --set RIPPLE_GLOW 0
```

`!motion` 이 생긴 이유가 이 합치기다. 소스만 보고 판정하면 합친 파일은 그레인을
0 으로 둬도 `time` 이 남아 있으니 늘 켬이 되고, 그러면 **합치는 것 자체가 회귀가
된다** — 손잡이로 끌 수는 있는데 배터리는 계속 나가는 상태다. 선언하는 방식과 값이
바뀔 때마다 다시 판정하는 이야기는 [손잡이](../knobs.ko.md) 에 있다.

합치는 것이 공짜이려면 지켜야 하는 둘 — 비싼 선택 작업을 유니폼 분기로 감싸는
것과, 그것을 여닫는 손잡이에 `!motion` 을 다는 것 — 은
[셰이더](../shaders.ko.md#손잡이로-끄는-것이-공짜여야-한다) 에 있다.

## 메뉴가 유리 아래로 깔리던 것

**이건 고친 버그이고, 메뉴 막대 UI 를 붙이기 전에는 아무도 몰랐다.**

오버레이는 `CGShieldingWindowLevel()` 에 있다. 그 값이 2147483628 인데 메뉴의
드롭다운 창은 101(`kCGPopUpMenuWindowLevel`), `NSAlert` 과 `NSOpenPanel` 은 8 이다.
곧 **상태 항목을 눌러서 나오는 메뉴가 오버레이 아래로 깔린다.** 화면을 빨강으로
덮고 메뉴를 연 뒤 스크린샷을 찍으면 메뉴가 한 픽셀도 안 보인다.

메뉴 막대의 `◲` 가 내내 보였던 것은 메뉴 막대의 주인이 윈도서버라서 **캡처에
들어오기** 때문이다 — 유리를 통해 비쳐 보이던 것이다. 드롭다운은 우리 앱이
주인이라 캡처에서 빠지고(앱 단위 제외) 레벨로도 아래에 있다. 비치지도 않고 보이지도
않는다. 항목이 넷일 때는 외워서 눌렀지만 슬라이더가 들어간 순간 그럴 수 없게 됐다.

고친 방법은 **메뉴가 열려 있는 동안만** 오버레이를 레벨 100 으로 내리는 것이다.
일반 창(0) · 떠 있는 창(3) · 모달 패널(8) · 메뉴 막대(24)는 그대로 덮이므로
달라지는 것은 우리 메뉴 하나뿐이다. 대화상자는 반대로 자기 레벨을 shielding 위로
올린다.

## `!motion` 을 붙일 때 실제로 잰 것

```
crt.frag 기본값                      redraw = true
crt.frag 흐르는 손잡이 전부 0        redraw = false
crt.frag GRAIN 만 되살림             redraw = true
water/still.frag 기본값               redraw = true
print/riso.frag (time 을 안 읽음)     redraw = false
crt.frag(0) → water/still.frag        redraw = true    ← 뒷칸이 흐른다
crt.frag(0) → print/riso.frag         redraw = false
```

선언이 없는 셰이더는 예전 그대로 소스만 보고 판단한다. 확인할 때 `still.frag`
에는 아직 표시가 없었고, 지금은 `SPEED`·`CLICK` 에 붙어 있다. `riso.frag` 도
그 뒤에 지워졌다 — 이 표는 **그때 실제로 잰 것**이라 이름을 바꿔 적지 않았다.
같은 줄을 지금 확인하려면 `print/paper.frag` 이 대신한다. 그쪽도 `time` 을
안 읽는다.

## 잠들었다 깨면 얼어 있던 화면

셰이더를 켜 둔 채로 덮개를 닫았다 열면 화면이 이상하게 돌아왔다. 셰이더는 분명히
살아 있는데 — 그레인이 움직이고 험 바가 흐른다 — 그 아래 그림이 덮개를 닫기 전의
바탕화면이다. 커서는 멀쩡히 움직인다. 윈도우 서버가 오버레이 위에 따로 그리는 것이라
애초에 셰이더를 통과하지 않기 때문이다. `--reload` 로는 아무것도 바뀌지 않는다.
셰이더를 다시 읽는 일과 캡처는 상관이 없다. 메뉴 막대에서 끄고 다시 켜면 낫는데,
그건 알고 있어야 할 이유가 없는 지식이다.

실제로 일어나는 일은 ScreenCaptureKit 의 한 줄이다.

```
SCStreamErrorDomain code -3815   Failed to find any displays or windows to capture
```

화면이 사라지면 스트림은 멈추는 게 아니라 **끝난다.** `didStopWithError` 가 오고,
깨어나도 아무것도 되살리지 않는다. 맨 스트림에 1 초 눈금을 붙여 잰 것 — 덮개도
시스템 절전도 아닌, 화면 절전만으로:

```
t=  5s  complete=47  ageOfLastComplete=0.1s
        !! didStopWithError -3815
t=  6s  complete=54  ageOfLastComplete=0.4s     ← 날아오던 마지막 프레임들
t= 28s  complete=54  ageOfLastComplete=22.4s    ← 화면은 이미 7 초째 깨어 있다
```

눈에 보이는 그 얼어붙음은 그 위에 앱이 스스로 얹은 것이다. 재그리기 타이머는 정지
화면에서 손잡이를 돌려도 뭔가 그려지도록 마지막 프레임을 쥐고 있는데
([정지 화면에서 슬라이더가 안 듣던 것](../knobs.ko.md#정지-화면에서-슬라이더가-안-듣던-것)),
그 프레임 — 덮개를 닫기 전의 그것 — 을 주사율대로 영원히 셰이더에 밀어 넣고 있었다.
오류가 왔을 때 창을 내리는 것도 소용이 없었다. 바로 다음 재그리기 눈금이 프레임이
도착한 것으로 세어져 창을 도로 올렸다.

그래서 세 가지를, 중요한 순서대로.

1. **스트림이 멈추면 그리기도 멈춘다.** 재그리기 타이머를 끄고 쥐고 있던 프레임을
   버린다. 다른 게 어떻게 잘못되든 죽은 스트림이 살아 있는 척할 수는 없게 된다.
2. **스트림을 다시 연다.** 처음 4 초는 0.5 초마다, 그 뒤로는 5 초까지 늘려 가며,
   누군가 이 캡처를 원하는 동안 계속. 화면이 꺼져 있는 동안은 모든 시도가 같은
   -3815 로 실패하는데 그게 맞다 — 화면이 돌아온 뒤에 걸리는 한 번이 전부다.
3. **숫자로 말하게 한다.** `--status` 에 `stale`(**스트림에서** 프레임이 온 지 몇
   초인지. 재그리기와 nudge 는 이 값을 건드리지 않는다)과 `restarts` 가 생겼다.
   기존 `fps` 로는 이걸 볼 수 없었다. 재그리기가 켜져 있으면 덮개와 함께 죽은
   캡처도 멀쩡한 60 을 계속 보고한다.

깨어남 알림(`didWake`, `screensDidWake`)도 붙였지만 그건 지름길일 뿐이다. 후퇴
간격을 취소해서, 깨어난 뒤 셰이더 없는 화면을 최대 5 초씩 보고 있지 않게 한다.
일부러 이걸 본체로 삼지 않았다. 같은 탐침을 맨 프로세스로 돌렸을 때는 알림이 아예
오지 않았고, 알림이 오는 것에 기대는 복구는 오지 않을 수도 있는 복구다. 실제로
알림은 **화면이 돌아오기 전에** 온다 — 이 기계에서는 7 초쯤 먼저 — 그래서 결국
붙이는 것은 재시도 쪽이다.
