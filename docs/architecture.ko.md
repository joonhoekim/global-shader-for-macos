# 구조

*[← README](../README.ko.md)  ·  [English](architecture.md)*

## 왜 이 구조밖에 없는가

하이프랜드는 자기가 합성기라서 마지막 합성 한 번에 셰이더를 끼워 넣는다. macOS
에서는 그 자리에 윈도서버가 있고, 거기에는 공개된 훅이 없다. 그래서 남는 길은
셋이고, 그중 이 레포의 셰이더를 돌릴 수 있는 것은 하나뿐이다.

| 길 | 지연 | 권한 | `tex` 를 읽나 |
|---|---|---|---|
| 감마 LUT (`CGSetDisplayTransferByTable`) | 0 | 없음 | **못 읽는다** — 채널별 1D 곡선이 전부다 |
| 투명 오버레이 + 블렌드 모드 | 0 | 없음 | **못 읽는다** — 위에 덧그리기만 된다 |
| **ScreenCaptureKit → Metal → 오버레이** | 한 프레임 남짓 | 화면 기록 | **읽는다** |

`crt.frag` 의 곡률·색수차·블룸·초점은 전부 자기 픽셀 **밖**을 읽는다. 화면을
텍스처로 손에 넣지 못하면 그 넷이 다 사라지고 스캔라인과 비네트만 남는다. 그건
다른 셰이더지 같은 셰이더가 아니다. 그래서 캡처 방식이다.

즉 지연·권한·배터리는 취향으로 고른 대가가 아니라, `tex` 를 읽는 값이다.

## 흐름

```
SCStream(디스플레이, 우리 앱 제외)
  → CVPixelBuffer(BGRA, sRGB)
  → CVMetalTextureCache            (IOSurface 공유, 복사 없음)
  → 프래그먼트 셰이더 한 번
  → CAMetalLayer                   (CGShieldingWindowLevel 의 보더리스 창)
```

## 되먹임 — 이 프로그램의 유일한 치명적 실패

오버레이가 자기 출력을 다시 찍으면 매 프레임 셰이더가 자기 결과에 또 걸린다.
곡률이 거듭 밀고 블룸이 거듭 쌓여서 화면이 **이상한 그림으로 수렴한다.** 잔상처럼
보이지만 잔상이 아니다 — 되돌아오지 않는다.

막는 것이 두 겹이고, 둘 다 필요하다.

**1. 스트림에서 우리 앱을 뺀다** (`SCContentFilter(excludingApplications:)`).
pid 로 나를 찾고, 번들 ID 가 **비어 있지 않으면** 같은 번들의 다른 프로세스도
함께 뺀다. 창 단위로 빼는 API 도 있지만 창은 띄운 뒤에야 목록에 뜨고 배치가
바뀔 때마다 다시 찾아야 해서, 앱 단위가 더 튼튼하다.

빈 문자열일 때 매칭하면 안 된다 — `SCRunningApplication.bundleIdentifier` 는
비어 있을 수 있고(알맹이 바이너리를 직접 돌리면 그렇다), 빈 값으로 비교하면
번들 ID 없는 남의 프로세스까지 캡처에서 빠져 화면에 구멍이 난다.

**하지만 이것만으로는 두 번째 인스턴스를 못 막는다.** `excludingApplications` 가
받는 `SCRunningApplication` 은 **프로세스** 단위다. 같은 앱이어도 두 번째 프로세스는
첫 번째의 스트림에서 안 빠진다. 둘이 뜨면 서로의 오버레이를 찍는다. 측정값:

```
A 마커 되읽기  74.3%     ← 두 인스턴스, 방어 없음
B 마커 되읽기 100.0%
```

**2. 창 자체를 안 찍히게 한다** (`NSWindow.sharingType = .none`).
창의 성질이라 누가 찍든 걸린다 — 두 번째 인스턴스든 다른 녹화 도구든. 같은 시험:

```
A 마커 되읽기 0.0%       ← 두 인스턴스, sharingType = .none
B 마커 되읽기 0.0%
```

여기에 **인스턴스 잠금**(`flock`)이 1차 방어로 붙어서 두 번째 실행은 아예 거절한다.
오버레이는 "화면이 좀 다르게 보이는 것"이라 두 번 띄웠는지 눈으로 알기 어렵다 —
사람이 조심하는 데 기댈 수 없는 자리다. flock 은 프로세스가 죽으면 커널이 풀어
주므로 크래시 뒤에 낡은 잠금이 남지 않는다.

대가: **스크린샷과 화면 녹화에 셰이더가 안 담긴다.** 찍으면 원래 화면이 나온다.
`--capturable` 로 끌 수 있지만, 그러면 다른 캡처 도구가 우리 출력을 되먹일 수 있다.

### 재현과 확인

```sh
global-shader --diag --exit-after 10 shaders/crt/crt.frag
```

셰이더 위에 좌상단 64px 마커를 덧그리고, 다음 프레임의 **캡처**에서 그 자리를
되읽는다. 0% 면 정상, 높으면 되먹임이다. 마커는 셰이더와 따로 노는 패스라 실제로
걸 셰이더 그대로 잴 수 있다 — 되먹임은 무거운 셰이더에서 드러나므로 통과
셰이더로만 되는 진단은 쓸모가 없다.

일부러 되먹임을 만들어 보려면 `--allow-multiple --capturable` 로 둘을 띄운다.

## GLSL → MSL

`glslang` 으로 SPIR-V, `spirv-cross` 로 MSL, 그걸 런타임에 `makeLibrary(source:)`.

두 도구를 실행할 때 찾는 자리가 다섯이고, 앞의 것이 이긴다 — `GS_GLSLANG` /
`GS_SPIRV_CROSS` 환경변수, 번들 안 `Contents/Helpers/`, `build.sh` 가
`Sources/Generated.swift` 에 박아 둔 절대경로, 홈브루 prefix
(`/opt/homebrew/bin` · `/usr/local/bin`), `PATH`.

**홈브루 prefix 를 손으로 적는 이유가 있다.** Finder 나 launchd 로 띄운
프로세스의 `PATH` 는 `/usr/bin:/bin:/usr/sbin:/sbin` 뿐이라 거기에
`/opt/homebrew/bin` 이 없다. 터미널에서는 되는데 아이콘으로 띄우면 안 되는
종류라, 안 겪어 보면 셰이더 탓을 하게 된다.

손으로 짠 치환기를 안 쓴 이유는 하나다. 이 레포가 돌려야 하는 것은 `fwidth` 와
16탭 루프가 든 물건이라, 치환기는 어느 표현식에서 **조용히** 틀린 값을 낸다.
틀린 걸 화면을 보고 알아채야 하는 도구는 쓸모가 없다. 표준 경로는 못 옮기면
에러로 죽는다.

## 규약 둘

파일에 `mainImage(` 가 있으면 셰이더토이, 없으면 하이프랜드로 알아본다.

**하이프랜드** — 이름과 뜻이 `decoration:screen_shader` 와 같다.

| | |
|---|---|
| `tex` | 화면 한 장. (0,0) 이 좌상단 |
| `screen_size` | 이 화면의 픽셀 크기 |
| `pointer_position` | 커서. 0..1, 좌상단 원점 |
| `time` | 건 뒤로 흐른 초 |
| `pointer_pressed_positions[32]` | 최근 클릭. `[0]` 이 가장 최근 |
| `pointer_pressed_times[32]` | 그 클릭 **이후** 흐른 초 |

`#version` · `in vec2 v_texcoord` · `out vec4 fragColor` · 위 유니폼 선언은
로더가 걷어내고 자기 것으로 갈아 끼운다. 그래서 하이프랜드용 파일을 그대로
넣어도 되고, 그 파일이 리눅스에서 계속 돌아도 된다.

**셰이더토이** — `iChannel0` `iResolution` `iTime` `iMouse` `iFrame`.
`fragCoord` 는 규약대로 좌하단 원점이고, `texture(iChannel0, ...)` 도 같이
뒤집어 준다.

## 안전장치

화면 전체를 덮는 창이라, 잘못됐을 때 고치러 갈 화면까지 같이 없어지면 안 된다.

- 창은 **첫 프레임을 그린 뒤에** 뜬다. 권한이 없거나 캡처가 안 붙으면 아무것도
  안 덮는다.
- 셰이더 컴파일이 실패하면 죽지 않는다. 첫 실행이면 통과 셰이더로, 리로드 중이면
  **지금 걸린 것을 그대로** 둔다. 오타 하나가 검은 화면이 되지 않는다.
- 오버레이는 `ignoresMouseEvents` 라 클릭이 전부 아래로 간다. 메뉴 막대의 상태
  항목은 셰이더 너머로 보이면서 눌리기도 한다 — 셰이더가 화면을 알아볼 수 없게
  만들어도 여기로 나올 수 있다.
- 캡처가 멈추면 그 화면의 창을 내리고 **스트림을 새로 연다.** 덮개를 닫거나 화면이
  저절로 꺼지면 스트림은 멈추는 게 아니라 SCK 가 끝내 버리고
  (`SCStreamErrorDomain -3815`, "Failed to find any displays or windows to capture")
  깨어나도 아무것도 되살리지 않는다. 창을 내리는 건 절반이고, 나머지 절반은 죽은
  스트림이 남긴 프레임을 더 이상 그리지 않는 것이다 — 그러지 않으면 덮개를 닫기
  전의 그림 위에서 셰이더만 계속 움직이고, 그게 눈에는 잘 돌아가는 것처럼 보인다.
  [잠들었다 깬 화면](notes/history.ko.md#잠들었다-깨면-얼어-있던-화면) 참고.
- 두 번째 인스턴스는 거절한다. 그 자체가 되먹임이기 때문이다(위 참고).
- 파일 저장은 0.4 초 폴링으로 잡는다. kqueue 가 아닌 건 vim·VS Code 가 저장할 때
  파일을 새로 쓰고 rename 하기 때문이다 — fd 를 잡아 두는 감시는 첫 저장 뒤에
  죽은 inode 를 본다.
